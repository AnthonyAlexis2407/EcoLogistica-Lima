# Evaluación de Accesibilidad Web (WCAG)

**Nombre del Proyecto:** EcoLogística Lima - Optimizador de Rutas Sostenibles para DistriRápido S.A.C.  
**Nivel de Conformidad Objetivo:** WCAG 2.1 / 2.2 Nivel AA  
**Herramientas Utilizadas:** axe-core 4.14.0 (reglas de las etiquetas `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa` y `wcag22aa`) ejecutado en Google Chrome 148 (modo sin interfaz), más revisión manual de teclado, foco y reflujo en 375 px  
**Fecha de Evaluación:** 2026-10-20  
**Versión del Documento:** V_1_0_0

[← Volver al README Principal](../../../README.md)

**Alcance y método.** Aplicación en ejecución local (`src/frontend`, servidor de desarrollo de Vite, API en local con los datos semilla). Se evaluaron 6 pantallas con la sesión de un administrador: inicio de sesión, Dashboard, Vehículos (lista y ventana de registro) y Pedidos (lista y ventana de registro); las pantallas autenticadas se midieron también a 375 px de ancho (móvil). **Limitaciones:** las herramientas automáticas detectan solo una parte de los criterios de WCAG; no se usó Lighthouse ni WAVE, no se probó con un lector de pantalla (NVDA, VoiceOver) y varios criterios de WCAG 2.2 (por ejemplo 2.5.8 tamaño del objetivo) no se verificaron. Los porcentajes de la sección 1 son porcentajes de **reglas automáticas aprobadas**, no una certificación de conformidad AA.

## 1. Resumen de Accesibilidad por Principios

Cada cifra cuenta reglas de axe aplicables a cada pantalla y ancho evaluados (6 combinaciones de pantalla y ancho para las autenticadas, más el inicio de sesión). Antes = código del Sprint 2; después = código con las correcciones de este sprint.

| Principio | Antes | Después | Observaciones |
|---|---|---|---|
| **Perceptible** | 81,3 % (26 de 32 aprobadas) | **100 %** (32 de 32) | Se corrigió el contraste de color (1.4.3) y el desbordamiento horizontal en móvil (1.4.10, revisión manual). Idioma `es`, título y metaetiqueta de ajuste de ventana presentes. |
| **Operable** | 100 % (26 de 26) | **100 %** (26 de 26) | Sin fallos automáticos. A mano: el foco es visible al recorrer con Tab los enlaces, botones y campos; las ventanas ahora se cierran con Escape (2.1.1). Falta comprobar la trampa de foco dentro de los modales. |
| **Comprensible** | 100 % (16 de 16) | **100 %** (16 de 16) | Todos los campos de los formularios tienen etiqueta visible asociada; los errores del servidor se muestran en texto dentro del formulario. El idioma de la página es español. |
| **Robusto** | 92,0 % (46 de 50 aprobadas) | **100 %** (50 de 50) | Se dio nombre accesible a los filtros y a los botones de cierre; los modales declaran `role="dialog"` y `aria-modal`. |

Resultado de la auditoría por pantalla (todas las reglas AA de axe): **antes 11 incumplimientos de regla repartidos en 5 pantallas (3 reglas distintas: `color-contrast`, `select-name` y `button-name`); después, 0 incumplimientos en las 6 pantallas.** El inicio de sesión no tenía fallos antes ni después.

## 2. Hallazgos Principales y Correcciones

| Criterio de Conformidad | Problema Detectado | Componente Afectado | Solución Aplicada |
|---|---|---|---|
| 1.4.3 Contraste mínimo (AA) | Texto con relación de contraste menor a 4,5:1: el verde de marca `#059669` sobre blanco daba 3,77:1 (subtítulo del logo, enlace activo del menú, indicadores de las tarjetas); el gris `#94a3b8` daba 2,56:1 (títulos de sección del menú, fechas y subtítulos); el rojo `#ef4444` del botón "Cancelar" daba 3,76:1; el indicador "API Online" (`#34d399` sobre verde claro) daba 1,7:1 y la insignia "Activo" quedaba en 2,5:1 por una opacidad de 0,6 | Menú lateral, tarjetas del Dashboard, tablas de Vehículos y Pedidos, botón Cancelar, barra superior | Se ajustaron los colores base del diseño: `--color-primary` a `#047857` (5,48:1 sobre blanco y 5,21:1 sobre el verde claro), `--color-text-muted` a `#64748b` (4,76:1), `--color-danger` a `#dc2626` (4,83:1); se quitó la opacidad del elemento "JWT + RBAC" y el indicador de la API usa `#047857` (4,87:1) |
| 4.1.2 Nombre, función, valor (A) | El filtro de estado de las listas no tenía etiqueta: un lector de pantalla lo anunciaba como "lista desplegable" sin propósito (regla `select-name`, impacto crítico) | Filtro de estado en Vehículos y Pedidos | Se añadió `aria-label="Filtrar por estado"` |
| 4.1.2 Nombre, función, valor (A) | El botón con la "X" para cerrar la ventana no tenía texto accesible (regla `button-name`, impacto crítico) | Modales de registro de Vehículos y Pedidos | Se añadió `aria-label="Cerrar ventana"` y `title`; además los modales declaran `role="dialog"` y `aria-modal="true"` (corregido junto con la incidencia S6848 de SonarQube) |
| 1.4.10 Reflujo (AA) | A 375 px de ancho la página se desplazaba horizontalmente (hasta 674 px de ancho): el menú lateral tenía 280 px fijos y no existía ninguna regla `@media`; esto también contradice RES-06 (funcionar en móviles y conexiones lentas). Detectado por revisión manual | Menú lateral, barra superior, Dashboard, Vehículos y Pedidos | Se añadió una regla `@media (max-width: 900px)` en `index.css`: el menú pasa a una barra superior que ajusta sus elementos, la barra de título ajusta líneas y las tarjetas se apilan. A 375 px el ancho de página es 375 px; las tablas conservan su propio desplazamiento interno |
| 2.1.1 Teclado (A) | Las ventanas de registro no se podían cerrar con la tecla Escape (revisión manual) | Modales de Vehículos y Pedidos | Se agregó un manejador de `keydown` para Escape mientras el modal está abierto |
| 4.1.3 Mensajes de estado / veracidad del contenido (AA) | La barra superior afirmaba "API Online · 100% Operativo" como texto fijo, aunque la API estuviera caída (información engañosa para quien usa lector de pantalla o conexión inestable) | Barra superior | Ahora consulta `/api/health` y muestra "API conectada", "API sin conexión" o "Verificando API…" (con pruebas automatizadas de los dos casos) |

## 3. Pruebas y reproducción

- Pruebas del frontend que protegen las correcciones: `el filtro y el botón de cierre tienen nombre accesible y Escape cierra el modal` (Vehículos y Pedidos) y `muestra el estado real de la API` / `avisa cuando la API no responde` (App). La suite completa suma 60 pruebas del frontend y 36 del backend en verde.
- Para repetir la auditoría: levantar la API y el frontend en local, iniciar sesión con un usuario de los datos semilla (`python -m app.seed`), instalar `axe-core` y ejecutarlo en cada pantalla con las etiquetas `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa` y `wcag22aa`; o bien usar la extensión axe DevTools o Lighthouse de Chrome sobre las mismas pantallas.
